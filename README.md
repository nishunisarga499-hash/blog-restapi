# Blog REST API with CRUD Operations

A RESTful blog API built with **Node.js** and **Express.js** for the *Web Development – Week 06 Minor Project*.
Users can create, read, update and delete blog posts through JSON endpoints that follow REST conventions, return proper
HTTP status codes and validate every input.

Besides the required CRUD features, the project implements **all of the bonus items**: MongoDB integration, JWT
authentication, pagination, search & filtering, Swagger documentation and Render deployment configuration.

## 1. Project overview

The API manages **blog posts**. Each post has:

| Field | Description |
|-------|-------------|
| `id` | Unique id generated by the server |
| `title` | Post title |
| `content` | Post body |
| `author` | Author name |
| `category` | Category (e.g. `Backend`, `Frontend`) |
| `createdAt` | Created date – set by the server (ISO 8601) |
| `updatedAt` | Last modified date – maintained by the server |

By default anyone can use the CRUD endpoints (exactly what the assignment asks for). Setting `AUTH_REQUIRED=true`
locks the write endpoints (create / update / delete) behind a JWT, while reading stays public.

**Request flow:** `route → (middleware) → controller → validator → repository → JSON response`.

## 5. Installation steps

Prerequisites: **Node.js 18 or newer** and npm. (MongoDB is only needed if you choose the `mongo` driver.)

```bash
# 1. Get the code
git clone <your-repository-url>
cd blog-rest-api

# 2. Install dependencies
npm install

# 3. Create your environment file
cp .env.example .env        # Windows: copy .env.example .env
#    then edit .env and set JWT_SECRET to a long random string

# 4. (Optional) add sample posts
npm run seed

# 5. Start the server
npm start                   # or: npm run dev   (auto-restarts on changes)
```

The API is now running at **http://localhost:3000** and the interactive docs at **http://localhost:3000/api-docs**.

> **Seeding note (`file` driver):** the server loads `data/posts.json` once at start-up and keeps it in memory. Run
> `npm run seed` *before* `npm start` (or restart the server afterwards); seeding while the server is running is not
> picked up, and the server's next write would overwrite the seeded file. With `STORAGE_DRIVER=mongo` this does not apply.

Generate a strong secret with:
`node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`

| Script | Purpose |
|--------|---------|
| `npm start` | Start the server |
| `npm run dev` | Start with auto-reload |
| `npm test` | Run the automated test suite |
| `npm run seed` | Add 6 sample posts (`-- --force` replaces existing posts). **Run it while the server is stopped** (see note below) |
| `npm run postman:build` | Regenerate the Postman collection |

## 7. API endpoints

### Blog posts

| Method | Endpoint | Description | Success | Errors |
|--------|----------|-------------|---------|--------|
| `POST` | `/posts` | Create a new blog post | `201` | `400`, `401*` |
| `GET` | `/posts` | Retrieve all blog posts (search / filter / sort / paginate) | `200` | `400` |
| `GET` | `/posts/:id` | Retrieve a specific blog post | `200` | `400`, `404` |
| `PUT` | `/posts/:id` | Update an existing post (any of title, content, category, author) | `200` | `400`, `401*`, `404` |
| `PATCH` | `/posts/:id` | Same as `PUT` | `200` | `400`, `401*`, `404` |
| `DELETE` | `/posts/:id` | Delete a blog post | `200` | `400`, `401*`, `404` |

\* `401` only occurs when the server runs with `AUTH_REQUIRED=true`.

**Query parameters for `GET /posts`**

| Parameter | Example | Meaning |
|-----------|---------|---------|
| `search` | `?search=express` | Case-insensitive match in title, content, author and category |
| `category` | `?category=Backend` | Exact category (case-insensitive) |
| `author` | `?author=Asha Rao` | Exact author (case-insensitive) |
| `sort` | `?sort=title` / `?sort=-createdAt` | `createdAt`, `updatedAt`, `title`, `author`, `category`; prefix `-` = descending |
| `order` | `?order=asc` | `asc` or `desc` (default: newest first) |
| `page`, `limit` | `?page=2&limit=5` | Pagination. `limit` ≤ 100 (default 10 when paginating) |

Parameters can be combined: `GET /posts?category=Backend&search=api&sort=-createdAt&page=1&limit=5`.
When neither `page` nor `limit` is sent, **all** matching posts are returned.

### Authentication (bonus)

| Method | Endpoint | Description | Success | Errors |
|--------|----------|-------------|---------|--------|
| `POST` | `/auth/register` | Create an account, returns a JWT | `201` | `400`, `409`, `429` |
| `POST` | `/auth/login` | Log in, returns a JWT | `200` | `400`, `401`, `429` |
| `GET` | `/auth/me` | Current user (needs token) | `200` | `401` |

### System

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/` | API information |
| `GET` | `/health` | Health check (used by Render) |
| `GET` | `/api-docs` | Swagger UI |
| `GET` | `/api-docs.json` | Raw OpenAPI spec |

## 9. Validation rules and error handling

**Post fields** (checked after trimming whitespace)

| Field | Required on create | Rule |
|-------|--------------------|------|
| `title` | yes | string, 3–150 characters |
| `content` | yes | string, 10–20 000 characters |
| `author` | yes | string, 2–100 characters |
| `category` | yes | string, 2–50 characters |

- On update every field is optional but at least one must be sent.
- `id`, `createdAt` and `updatedAt` are read-only and silently ignored if sent; any other unknown field → `400`.
- Ids must be valid (UUID for `memory`/`file`, ObjectId for `mongo`) → otherwise `400`.
- Query parameters are validated too (`page ≥ 1`, `1 ≤ limit ≤ 100`, whitelisted `sort` fields, …).
- Request bodies are limited to 100 KB.

**Status codes used**

| Code | Used for |
|------|----------|
| `200 OK` | Successful read / update / delete |
| `201 Created` | Post or user created |
| `400 Bad Request` | Validation failure, malformed JSON, invalid id or query |
| `401 Unauthorized` | Missing / invalid / expired token, wrong login |
| `404 Not Found` | Post or route does not exist |
| `409 Conflict` | Email already registered |
| `413 Payload Too Large` | Body larger than 100 KB |
| `429 Too Many Requests` | Auth rate limit exceeded |
| `500 Internal Server Error` | Unexpected failure (details are logged, never sent to the client) |

All errors share one shape: `{ "success": false, "error": { "status", "message", "details?" } }`.

## 10. Data storage options

The storage layer is hidden behind a repository interface, so the controllers do not care where data lives.
Choose with `STORAGE_DRIVER`:

| Driver | Description | Use for |
|--------|-------------|---------|
| `memory` | Array in RAM | Tests, demos (data lost on restart) |
| `file` (default) | JSON files in `./data` – atomic writes, serialised through a queue | Local development, no database needed |
| `mongo` | MongoDB through Mongoose (bonus) | Deployment, production |

To use MongoDB locally or with Atlas:

```bash
# .env
STORAGE_DRIVER=mongo
MONGODB_URI=mongodb://127.0.0.1:27017/blog-api      # or your Atlas connection string
```

> **Note on testing:** the `memory` and `file` drivers are covered by the automated tests and the Postman run.
> The `mongo` driver shares the same interface, controllers and validators, but the automated tests do not connect
> to a live MongoDB server. After configuring `MONGODB_URI`, run the Postman collection (section 12) against your own
> instance to confirm it end to end.

## 11. Authentication (JWT)

1. **Register** – `POST /auth/register` with `{ "username", "email", "password" }` (password 8–72 characters, stored as a bcrypt hash).
2. **Login** – `POST /auth/login` with `{ "email", "password" }` → returns `data.token`.
3. **Use the token** – send `Authorization: Bearer <token>` on protected requests.

```bash
TOKEN=$(curl -s -X POST localhost:3000/auth/login -H "Content-Type: application/json" \
  -d '{"email":"asha@example.com","password":"S3cure-passw0rd"}' | node -p "JSON.parse(require('fs').readFileSync(0)).data.token")

curl -X POST localhost:3000/posts -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"title":"Protected post","content":"Created with a valid token.","author":"Asha","category":"Security"}'
```

Set `AUTH_REQUIRED=true` to make `POST`, `PUT`, `PATCH` and `DELETE` on `/posts` require the token (reads stay public).
Security measures: bcrypt hashing, tokens pinned to HS256 and expiring (`JWT_EXPIRES_IN`), identical error for wrong
email vs. wrong password, a dummy bcrypt comparison for unknown emails (so timing does not reveal which accounts exist), rate limiting on `/auth`, `helmet` headers.

## 12. Testing instructions

### a) Automated tests

```bash
npm test
```

Runs **77 tests** with Node's built-in test runner and `supertest` (no server needs to be running, no database needed).
They cover all CRUD operations, validation, 404/400 paths, pagination / search / filter / sort, JWT authentication
(including expired, forged and `alg=none` tokens), rate limiting, Swagger, JSON-file persistence and concurrent writes.

### b) Postman / Thunder Client / Insomnia

1. Start the server (`npm start`).
2. Import **`postman/blog-rest-api.postman_collection.json`**
   - *Postman:* Import → select the file.
   - *Thunder Client (VS Code):* Collections → ⋯ → Import.
   - *Insomnia:* Import → From file (Postman v2.1 collections are supported).
3. Check the `baseUrl` collection variable (default `http://localhost:3000`).
4. Run the collection top-to-bottom (Postman *Runner*). Requests are numbered and chained: registering stores the
   token, creating a post stores `postId`, which later requests reuse.

The collection contains **27 requests / 55 assertions** covering every endpoint plus the error cases (400, 401, 404, 409).
It works with `AUTH_REQUIRED=false` and `true` because it sends the token it obtains.

Command-line run with newman:

```bash
npx newman run postman/blog-rest-api.postman_collection.json --env-var baseUrl=http://localhost:3000
```

### c) Manual testing with curl

See the examples in [section 8](#8-request-and-response-examples).

The recorded results of the automated and Postman runs are in **`docs/API_TEST_RESULTS.md`**.

## 13. Swagger documentation

Start the server and open **http://localhost:3000/api-docs**. Every endpoint, schema, parameter and response is
documented and can be tried directly from the browser. Click **Authorize** and paste a JWT to test protected endpoints
when `AUTH_REQUIRED=true`. The raw OpenAPI document is at `/api-docs.json`.

## 14. Deployment (Render / Railway)

Render's free disk is ephemeral, so deploy with the **MongoDB** driver.

1. **Database:** create a free cluster on [MongoDB Atlas](https://www.mongodb.com/atlas), add a database user, allow
   network access (`0.0.0.0/0` for a demo), and copy the connection string.
2. **Push the project to GitHub** (`.env` and `data/*.json` are git-ignored).
3. **Render:** *New → Blueprint* and select the repository (it reads `render.yaml`), or *New → Web Service* with
   - Build command: `npm ci --omit=dev`
   - Start command: `npm start`
   - Health check path: `/health`
4. **Environment variables** (Render dashboard):
   `NODE_ENV=production`, `STORAGE_DRIVER=mongo`, `MONGODB_URI=<your Atlas string>`,
   `JWT_SECRET=<long random string>`, optional `AUTH_REQUIRED=true`.
5. After the deploy, open `https://<your-service>.onrender.com/api-docs` and run the Postman collection with
   `baseUrl` set to that URL.

**Railway:** *New Project → Deploy from GitHub repo*, set the same environment variables; Railway detects Node.js and
runs `npm start` automatically.

## 15. Design decisions

- **Auth is opt-in (`AUTH_REQUIRED`)** – the assignment's core API is open CRUD, so it works out of the box; JWT protection
  is a one-line switch that demonstrates the bonus without breaking the basic requirement.
- **Repository pattern** – memory, JSON file and MongoDB implementations share one interface, so storage can be swapped
  without touching controllers.
- **`PUT` accepts partial bodies** – the assignment says users may modify "title, content, category, or author", so a
  client can send just the fields that change. `PATCH` is provided as an alias.
- **Pagination is opt-in** – `GET /posts` returns every post unless `page`/`limit` is given, matching "retrieve all blog posts".
- **Delete returns `200` with the deleted post** (rather than an empty `204`) so clients get a confirmation message.
- **Thin controllers, central error handling** – controllers throw `ApiError`; one middleware turns every error into JSON.
